# 生图检查与有界修正

2026-09-17，适用于普通预处理与 Pro 状态图。

## 已修复的链路问题

- 全身检查不再仅依赖长宽比与底边透明度。服务端将原始参考与生成候选一起送入视觉检查，覆盖完整性、留白、身份、服装、画风、肢体、姿态、背景八项。
- Pro 动作提示词包含与基础主图相同的二维画风、完整构图限制，并要求肢体数量和连接保持一致。
- 任何失败、不确定、检查服务不可用、报告版本过旧均不自动进入拆层。正常任务、历史恢复、手动提交和 Pro 自动分支都检查当前报告。
- 首次候选被明确拒绝后，最多自动修正一次；修正仍以原始参考为输入。保留每次候选、提示词和报告，不把失败图作为下一次的参考。
- 若完整性、身份、服装、画风、肢体和姿态都已通过，仅背景或留白未通过，先用现有 isnet-anime 分离背景；只有留白不足才在四边增加 12.5% 画布。仅背景不合格时维持原画布和位置，避免破坏动作图与中立图的对齐。人物不缩放、不重画；保留原图、透明前景、遮罩及数值报告。处理后再次检查全部八项，避免分割损伤光环、羽翼和手指被直接放行。
- 超时或扣费结果未知时不自动重放。重启时不会把第一张旧候选冒充第二次请求的成功结果。
- 现有图片可以单独复核，无需重新生图。最终模型的视觉验收仍独立保留。

## 真实复测

证据在 `outputs/image-stability-20260917/`，原始完整任务在本机 Relay 的 `state/prep/`。

- 较弱的 v1 检查模型漏掉了挥手 B 的第三只手，因此该版本作废。
- v2 使用 GPT-5.4；全身图与原始参考直接比较。曾尝试将局部放大图混在全局检查中，但会混淆构图判断，已移除。
- v2 拒绝三手图，挥手 A 通过。独立中立立绘任务两次生成后仍存在留白/背景问题，按预期停止，没有提交拆层。
- 单次通过不代表模型稳定性已经统计达标；报告中保留失败记录，不能只挑成功样本计算成功率。
- 校准发现 GPT-5.4 对正常二维明暗、参考未显示的鞋袜有误判。最终 v3 改为 GPT-5.5：同组测试保留正常二维画风判断，同时拒绝明确三维漂移与三手图。构图目标改为上下各约 10% 留白，保留约 5% 的验收下限。
- 最终启用 v4：仅检查副本统一展示高度，解决不同文件分辨率被误判为人物缩放的问题；明确按画布比例检查位置，生产图片不变。修复主图 `cd4c0bda7e824bcf8d62c90d90d99c65` 与挥手 `ef255f6020a44f81b0c5e616b4da9750` 均通过八项检查，分别保留 `accepted-base.png` 与 `accepted-wave.png`。本次未重建旧 MOC3。

## 运维

部署须同时包含 `worker/app/image_quality.py`、`prep_queue.py`、`pro_queue.py`、`foreground.py`。背景整理需要现有 `worker/requirements-foreground.txt` 依赖与 isnet-anime 权重；不可用时保留拒绝状态，不跳过检查。
视觉检查与 Image-2 使用已有 Gateway 凭据，并遵循已配置的系统 HTTPS 代理；不修改网络设置、不向前端传递凭据。
修改质检标准后应升级报告版本，历史通过不能直接作为新版通过。
