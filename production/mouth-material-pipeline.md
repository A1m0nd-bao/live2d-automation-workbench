# 嘴部素材链路 v1

## Pro 接入约定（2026-09-14）

归入 Pro：See-Through PSD → 嘴层定位校验 → 嘴部素材替换 → 多状态冲突检查 → 原生绑定 → Cubism 导出 → 语音与动作组合验收。

优先使用 See-Through 独立 mouth 层的原画布坐标，不另行猜测位置。Pro 合并报告现包含 mouth 候选层、边界、中心与审核项。独立候选仅表示已定位，不表示分割正确；混合 mouth_nose、缺失、重复或越界均不自动选取。表情组不作为基础嘴定位来源；需核对候选是否属于中立层。

替换应另存 PSD，并保持画布和锚点不变；六层素材共用一个坐标变换。原嘴层的薄边界仅用于定位，不能作为张嘴区域的裁切框。保留鼻子、脸与下巴；脸上存在烘焙旧嘴时停止自动替换。表情和语音须合成最终嘴型参数，不能同时显示两套嘴。

当前落地范围：Pro 清单和合并报告的定位审核入口。Ana 网页联调仍是运行时附加嘴部。自动 PSD 替换、原生六层绑定、队列与前端审核控件尚未完成；报告固定 replacementApplied=false、nativeRigVerified=false，不自动批准或改变原 PSD。不得把本节解释成全链路已经实现。

## 一张图生够什么

一张 2048×2048 双格素材板：上格上嘴线，下格下嘴线。同一张角色脸部参考、同一轮生成。不是九宫格，也不是让 AI 生 PSD。

口腔和舌头使用本项目独立绘制的几何形状与默认配色，不读取或复用学习工程。色彩和形状是初始通用模板，并非适用于所有角色：兽嘴、尖牙、写实唇等要单独处理。

上下肤色遮挡使用角色局部取色生成初稿。强渐变、腮红、唇影可能产生贴片接缝，必须验收；简单中值取色不能代替完整的肤色纹理匹配。

九个形态属于绑定阶段：嘴型 [-1,0,1] × 开口 [0,0.4,1]。本脚本仅交付素材和绑定契约，**不生成这九个形变**。

## 输入及提示词

`prompts/mouth-lines-v1.txt` 是完整提示词，每次准备任务保存一份快照。身份参考只允许原角色，不使用学习用 PSD/CMO 或其截图作生成参考。

配置 JSON（坐标必须对应输入图，不要照抄示例数字）：

```json
{
  "source": "/absolute/path/character.png",
  "face": {"left": 100, "top": 100, "width": 400, "height": 400},
  "skin": {"left": 250, "top": 320, "width": 20, "height": 20}
}
```

`face` 为完整正脸参考裁切；`skin` 是原图上的干净脸颊皮肤区域，避开嘴线、腮红、头发、阴影和透明像素。v1 不假装拥有自动人脸/肤色检测，先人工确认 ROI。

```bash
node scripts/mouth-materials.mjs prepare /absolute/config.json /absolute/new-job
node scripts/mouth-materials.mjs assemble /absolute/new-job /absolute/generated-sheet.png /absolute/new-materials
```

若提供的是白底图，必须显式添加 `--white`。近似去白会影响浅色/抗锯齿线条，结果仍需人工检查；拒绝不透明棋盘格背景，不自动改用另一模型重试。

## 如何生图

准备任务生成 `face-reference.png`、`prompt.txt`、`job.json`、`request.template.json`。可将前两者交给 Codex 内置生图，或在已有豆包接入中使用同样参考及提示词。

豆包请求模板沿用现有 `worker/app/prep_queue.py` 的 `/images/generations` 协议，但嘴部任务应独立使用 2048×2048，不得套用全身图提示词或 1536×2400 尺寸。模板中的模型 ID 和参考 data URL 必须由服务端填入，不包含凭据；它不是可以直接发送的最终请求。

这次未改动共享生图队列：队列目前只接受固定的全身提示词，没有为嘴部任务提供独立类型。下一步新增 `mouth_materials` 类型，持久化提示词版本、源图哈希、ROI、模板版本、返回原图、QA 状态；无自动付费重试。调用失败或素材不合格不得推进任务。

## 输出和验收门槛

- 原始生成图另存、不覆盖。
- 两格分别检查非空、细线范围、留白；归一化到相同宽度与中心。该检查不能证明语义正确，文字、额外线条、风格漂移仍需目视验收。
- 输出六张 PNG、六层 `mouth-materials.psd`、`neutral-review.png` 和 `manifest.json`。所有文件在新目录，拒绝覆盖已有目录。
- 通用模板不需要每次生图，但每个角色实例仍会输出独立配色文件，避免修改一个角色影响所有角色。
- PSD 舌层按口腔建立剪贴关系；导入 Cubism 后需检查是否正确转换为遮罩。
- 当前肤色遮挡轮廓是程序初稿，需匹配新嘴线边界，尤其闭嘴接缝。原脸旧嘴必须干净移除；本阶段不删除脸部像素。
- `needs_review` / `rigReady:false` 是固定输出，不存在自动批准开关。完成贴片/闭合/原嘴清除验收后，才可由后续绑定阶段消费。
- 验收范围：闭嘴不漏黑、嘴线不重影、肤色无明显接缝、九形态过渡、头部 X/Y/Z 组合、下巴轮廓稳定、原生 MOC 重导出一致性。
