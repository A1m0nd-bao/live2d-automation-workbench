# Pro 多状态队列

## 当前策略：仅特殊手势，严格串行

新任务仅允许挥手、叉腰、抱臂、思考；默认只选择挥手。表情不自动生图，保留已有表情素材及参数，不代表会自动补齐缺失绑定。生图与 See-Through 共用容量为 1 的执行信号量；Pro 调度一次只推进一个任务。单实例部署，不得启动多个 Relay 实例或 uvicorn workers，否则进程内信号量不能阻止跨进程并发。

基础立绘和基础 PSD 就绪后，前端提交 `/pro/jobs`。服务端把每个状态的提示词、参考图、生成编号、拆分编号持久化到 `MORPH_DATA_ROOT/pro/jobs.sqlite3`，依次驱动现有 Prep 和 See-Through 队列。

- 每个状态都以同一中立主图为参考，不串用上个状态输出。
- 重复提交同编号不重新生图；输入不同则 409。
- 服务重启后继续查询已有子任务。未知付费结果不自动重试。
- 单项重试需要明确确认；如果生图已成功，只重试拆分。
- 成功 PSD 保存在服务端，前端自动下载至 IndexedDB，收齐后本地合层。
- **合层不是服务端执行**：浏览器关闭不影响生成/拆分，重新打开后自动合层。
- 自动队列的合层保留源层序，不套用可能误伤衣领的排序模板。报告仍需视觉验收。
- 缺槽位、画布不一致或锚点漂移会停止合层并展示原因，不清除素材、不自动再次计费。
- `ready` 只代表 PSD 收齐，不代表人设、绑定、CMO3 或 MOC3 通过验收。

## 部署

Pro 状态抠图还需安装 `worker/requirements-foreground.txt`，并预先准备 rembg 的 isnet-anime 模型缓存。首次模型下载时间不计入正常任务耗时。本分支沿用 master 的基础生图提示词，没有同步本地待调整的提示词版本。

同时部署 `worker/app/main.py`、`prep_queue.py`、`pro_queue.py`，沿用原设备访问认证。单实例运行。先确认无进行中任务，再备份并重启 Relay。前端执行 `npm run build:pages`；不要在未合并分支前发布 master。

前端入口：任务详情 → Pro → 恢复／同步多状态队列。旧任务可点击启动；从新基础拆分完成的 Pro 任务自动启动。仅有本地 PSD 而没有基础服务端任务的工作流继续保留手动导入入口。

## 验证

`worker/test_pro_queue.py` 覆盖幂等、断点恢复、未知结果、单项拆分重试和输入冲突。使用临时 `MORPH_DATA_ROOT` 运行测试，避免访问生产数据库。
