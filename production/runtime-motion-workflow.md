# 原生运行包 → 动作预览流程 v1

确认基线：2026-09-13 的 Ana 小幅动作版。动作规范 ID：`ana-small-motion-v1`。

## 操作入口

工作台任务 → CMO3/模型验收窗口 → **原生 MOC3 交互验收** → 导入 Cubism 导出的 ZIP。

1. ZIP 必须只有一个 model3.json，且 MOC、纹理、物理、动作等引用文件齐全。拒绝外部 URL 与越界路径。
2. 先将原包保存在任务的本机 IndexedDB。导入新包时，原始/预览缓存成对原子更新，避免恢复旧派生包。
3. 同一份已验收 Ana MOC（SHA-256 精确匹配）自动追加 `MorphBaseline` 动作组的 9 段动作。原包原有动作不会删除或覆盖。
4. 其他 MOC 保留原有动作；用户可选择“试配 Ana 小幅动作规范”。缺少所需参数即停止，不生成空参数冒充绑定。参数匹配只允许试配，不代表外观合格。
5. 自动播放基准第 3 段手臂＋轻屈膝动作。默认/挥手由独立控制器平滑切换，不中断动作循环。手动参数可以释放。
6. “全部数据与代码”显示全部 JSON、物理数据、适配报告、当前执行源码及所有实时参数，可下载独立数据包。
7. “下载模型＋动作运行包”输出 MOC、纹理、原有 JSON、基准 motion3 和 model3 注册信息。派生包另存本机，下次进入同一任务恢复。

## 基线与边界

- 基准身体 XYZ **动作曲线**幅度是 v9 的 35%，眼睛、呼吸、手臂节奏保留；SDK 自然摆动与物理可能另有叠加。
- 膝动作曲线映射至左右 ±4°。左右腿手动旋转测试限 ±2°。当前绑定不是 v9 软膝网格，不宣称一模一样。
- 已验收 MOC 指纹：`97f14b10bb8924ba03c25f6751352170303c6a448afc4e3f822db950ce849711`。它是此前用户导出文件的精度字段修正测试版，**不是新的 Cubism 原生重导出**。
- 本集成不修改任何 MOC/CMO 二进制，也不代替 Cubism 原生导出。生成器中的动作参数小数精度修复另在 cmo3writer 中维护。
- 原始包保存在 `<task-id>:native-runtime`；派生包保存在 `<task-id>:native-runtime-prepared`。仅浏览器本地，不是云端备份，换机器需要下载/重新导入。
- 每帧图形变化可能来自待机或物理。因此“动作启动/存在位移”仅为诊断，不能自动勾选成品验收。Wave 同时比较顶点和图层透明度，避免漏掉换图型动作。
- 当前只有默认/挥手两种姿势绑定，不自动补图或补齐 v9 的扶腰、抱臂、思考。
- 基准数据来自项目中已验证的 v9/Hiyori 衍生动作；仓库只纳入动作 JSON 和流程代码，不纳入 Ana 原画、纹理、MOC、账号密钥。实际部署仍需遵守上游素材/SDK 授权。

## 验证与维护

`node --test tests/runtime-motion-workflow.test.mjs` 检查原包保护、幂等、未知模型、缺少参数、危险引用、MOC 记录对齐；最后一项使用未提交的本机 Ana 样本，不存在时明确跳过。

`tests/fixtures/runtime-workflow-preview.html` 是开发用同组件回归入口，不进入 Pages 构建产物。使用独立 IndexedDB 测试键，不动现有任务。需在 Vite 开发服务器下运行。

`scripts/freeze-ana-motion-baseline.py` 从本机已确认输出冻结动作 JSON。更新基准必须重新验证，不能仅改指纹绕过验收。

GitHub Pages 构建命令仍为 `npm run build:pages`；发布前按项目分支/PR 流程提交，不直接绕过 master 审核。
